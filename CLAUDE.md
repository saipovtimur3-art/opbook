# opbook — Операционная книга · VKO

Одностраничное приложение (`index.html`, весь код в одном файле) — операционный
чек-лист/справочник для двух точек в аэропорту Внуково: **Burger Heroes** (🍔)
и **Мо Бар** (🍹). Разделы: чек-листы смены, меню, финансы, состав команды,
штатное расписание, внешний вид, поставщики, тех. контакты, ЧС, правила
аэропорта, задачи менеджера, мотивация, обучение.

## Владелец / контекст

Владелец — не разработчик, новичок в этой теме. При любых правках или
объяснениях — простой пошаговый язык, без лишнего жаргона, без "кругов" —
сразу давать точный путь (какие кнопки нажать, что ввести), не заставлять
переспрашивать.

## Дизайн

Тема "корпоративный минимал": светлый фон, шрифт Inter, единый акцент
`--accent:#5457E5`. Цвета `--bh` (красный) и `--mobar` (коричневый) остаются
как смысловые — обозначают конкретную точку (в шапке, статус-чипах и т.д.),
их трогать не нужно без явного запроса.

## Хостинг и доступ — ВАЖНО

Сайт **больше не на Netlify**. Сейчас:

- **Хостинг:** Cloudflare Pages, проект `opbook`, домен `opbook.pages.dev`.
  С 05.08.2026 подключён напрямую к GitHub-репозиторию (git integration),
  **Production branch = `claude/create-application-sjh9ps`**, автодеплой
  включён (Automatic deployments: Enabled). Раньше был на прямой загрузке
  файла (direct upload) — это в прошлом, см. историю деплоев в Cloudflare,
  если нужно.
- **Доступ:** Cloudflare Access (Zero Trust) — вход по одноразовому коду на
  почту. Policy называется **«Доступ по почте»**, список разрешённых email
  редактируется в Cloudflare: Zero Trust → Access controls → Applications →
  opbook.pages.dev → policy «Доступ по почте» → Include → Emails.
- Identity provider: **One-time PIN** (добавлен явно; авто-дефолт на PIN не
  сработал, пока не удалили лишний IdP "Cloudflare" и не добавили PIN вручную).
- В `index.html` есть блок в самом низу (`ob-identity-bar`), который через
  `/cdn-cgi/access/get-identity` показывает email вошедшего и ссылку
  `/cdn-cgi/access/logout` — работает только когда сайт реально стоит за
  Cloudflare Access; локально/без Access просто не отображается, это ожидаемо.

### Как обновить сайт (деплой)

GitHub push теперь работает напрямую (обычный `git push` / GitHub MCP tools).
Причина прежней 403-блокировки ("Resource not accessible by integration"):
GitHub App "Claude" (owned by anthropics) был только **авторизован** на
уровне аккаунта, но никогда не был **установлен** (installed) ни на один
репозиторий — отсюда и ошибка. Исправлено 05.08.2026 через
`github.com/apps/claude` → Install → выбрать аккаунт `saipovtimur3-art` →
All repositories → Install & Authorize. Если снова появится 403
"Resource not accessible by integration" — первым делом проверить
`github.com/settings/installations` → должен быть установлен app "Claude"
(не просто присутствовать в "Authorized GitHub Apps", а именно быть
**установленным**).

Обновление сайта теперь простое:
1. Правишь `index.html` локально.
2. `git add` + `git commit` + `git push origin claude/create-application-sjh9ps`.
3. Cloudflare Pages сам подхватывает пуш и деплоит — ничего вручную загружать
   не нужно. Проверить результат: Cloudflare → Workers & Pages → opbook →
   Deployments (или сразу открыть opbook.pages.dev).

**Исторический подводный камень (актуален, только если когда-нибудь снова
придётся грузить файл вручную):** Windows часто скрывает расширения файлов,
из-за чего при переименовании легко получить `index.html.html` (сайт отвечает
HTTP 404 — файл не распознаётся как index). Решение: включить показ
расширений в проводнике (Вид → Показать → Расширения имён файлов) и
загружать через **folder**, не через одиночный file-drag — на одиночном
файле Cloudflare иногда сам дублирует расширение.

## Данные (Google Sheets, live через JSONP)

- **Выручка/финансы** (`REVENUE_SHEET_ID` в коде, `1wwb1fkPp7ZUht...`):
  вкладки называются `БХ <МЕСЯЦ> <ГОД>` и `МО БАР <МЕСЯЦ> <ГОД>` (например
  `БХ АВГУСТ 2026`). **Названия вкладок нужно вручную обновлять в коде
  каждый месяц** (`REVENUE_SHEET_NAMES` в `index.html`) — это НЕ определяется
  автоматически по текущей дате. Если попросят "переключить на новый месяц" —
  искать константу `REVENUE_SHEET_NAMES` и обновлять оба значения, названия
  вкладок сверять в реальной таблице (владелец может прислать скриншот).
- Ставка «План 1» (₽/пасс) в подписи под "Выполнение плана" — берётся **живьём**
  из заголовка таблицы каждой точки (регэксп по тексту ячейки), не хардкодится.
- «Выполнение плана» может показывать "—" не из-за бага, а потому что в
  таблице пуста колонка «Паспоток МВЛ» на нужные дни — без неё плановая сумма
  в рублях = 0, процент считать не из чего. Это объяснять владельцу как
  вопрос заполнения таблицы, не как баг кода.
- **Состав команды** (`TEAM_SHEET_ID`): вкладки `БХ` и `Мо - Бар`, не
  месячные, отдельная логика (`TEAM_SHEET_CANDIDATES`).

  (интерфейс Cloudflare/GitHub на английском), но общаться по-русски.
- Просить скриншот, когда неочевидно, что откроется дальше — не гадать.
- Если что-то не работает второй раз одинаково — не повторять тот же шаг,
  менять диагностику (например, смотреть детали деплоя, а не просто
  пересоздавать).
